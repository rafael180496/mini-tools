# Arquitectura actual — mini-tools

> Esto documenta el estado ACTUAL del código, mantenido a mano fase a fase. Para la intención funcional original (lo que se planeó construir, no siempre idéntico a lo que terminó existiendo — ver notas de desviación en [go-react-contract.md](go-react-contract.md) y en el [SKILL](../skills/mini-tools-patterns/SKILL.md)), ver [docs/SPEC.md](../../docs/SPEC.md).

## Stack

- Backend: Go 1.26 + Wails v2
- Frontend: React + TypeScript + Vite + Tailwind CSS v4 (estrategia `dark` por clase, ver `@custom-variant dark` en `frontend/src/styles/globals.css`)
- Oracle: `github.com/sijms/go-ora/v2` (driver `database/sql` `"oracle"`)
- PostgreSQL: `github.com/jackc/pgx/v5/stdlib` (driver `database/sql` `"pgx"`)
- SQLite: `modernc.org/sqlite` (driver `database/sql` `"sqlite"`, puro Go, sin cgo)
- SQL Server: `github.com/microsoft/go-mssqldb` (driver `database/sql` `"sqlserver"`, puro Go, sin cgo)
- Redis: `github.com/redis/go-redis/v9` (`redis.UniversalClient` — standalone/Cluster/Sentinel — path nativo paralelo, NO `database/sql`; ver excepción documentada en [.claude/rules/technical.md](../rules/technical.md) punto 2 y el detalle de diseño en [.claude/skills/mini-tools-patterns/SKILL.md](../skills/mini-tools-patterns/SKILL.md))
- MongoDB: `go.mongodb.org/mongo-driver/v2` (`*mongo.Client` — path nativo paralelo, NO `database/sql`, segunda excepción documentada del punto 2; sintaxis mongosh en el editor, vista de resultados JSON con color, browser de documentos editable, asistente de find)

Dep github.com/aymanbagabas/go-pty: Go puro, openpty por syscalls en Unix y ConPTY en Windows, sigue cross-compilando a Windows desde Mac sin cgo. Separado de /sshconn y no una rama adentro: una sesión local no tiene DSN, host, auth ni pool que compartir con un panel SFTP

Sin dependencias: los agentes se EJECUTAN como programas de terminal sobre el PTY de /localterm, no se integran por API — ver el doc del paquete. La autenticación la sigue manejando cada CLI; la app solo guarda, opcional y cifrada, una API key
  /agentctx     descubrimiento de QUÉ le ofrece un repositorio a un CLI agéntico: scan.go (skills en .claude/skills Y .github/skills, subagentes y comandos de .claude/, todo con su equivalente del home marcado como scope "user"; archivos de instrucciones CLAUDE.md/AGENTS.md/GEMINI.md/copilot, informando también los AUSENTES) + frontmatter.go (lector a mano de `name`/`description`, sin sumar un parser YAML al binario — regla 12). Solo lectura y tolerante con lo desconocido: un SKILL.md sin frontmatter se lista igual
  /agentchat    CLIs agénticos en modo HEADLESS, traducidos a un evento común (types.go + adapters.go + session.go + attach.go: imágenes pegadas o subidas, escritas fuera del repositorio y con limpieza por antigüedad + history.go: re-dibuja los mensajes al retomar, leyendo el transcript del CLI — completo en Claude Code, con heurística documentada en Codex, imposible en Antigravity porque guarda blobs binarios). Camino PARALELO al PTY de /localterm, no un reemplazo: aquel da la experiencia completa del CLI pero entrega bytes con ANSI; este da eventos tipados con los que se puede dibujar un chat. Adaptadores VERIFICADOS contra corridas reales guardadas en testdata/ (claude, antigravity, codex — tres formatos distintos entre sí); Gemini CLI no tiene porque no se pudo capturar. Un turno = un proceso; la continuidad la da el id de conversación del propio CLI. Modos de permiso por turno (consulta/plan/aprobar-cada-acción/automático/editar), los permisivos con aprobación explícita del usuario; **nunca se pasa la bandera que saltea TODOS los permisos**, que cubre además ejecutar comandos arbitrarios
  /agentapprove aprobación acción por acción: channel.go (socket Unix + timeout; **si no se puede preguntar, deniega**) + hook.go (re-exec como hook PreToolUse, el mecanismo que reemplazó a `--permission-prompt-tool`, que ya no existe en Claude Code 2.1.231) + settings.go. Verificado de punta a punta contra el CLI real, denegando y aprobando. **Corrección de deriva de doc:** este párrafo listaba un `mcpserver.go` ("servidor MCP de stdio, conservado por si otro CLI lo usa") que **no existe** — el paquete nunca tuvo ese archivo. Hoy la app **no tiene ningún servidor MCP**; lo que sí tiene es `/mcpconf`, que lee y edita la configuración MCP de los CLIs, que es otra cosa. El servidor MCP embebido es construcción nueva, planificada en [sistema-agentico-unificado.md](sistema-agentico-unificado.md) fase 6. **Nota de portabilidad:** `channel.go` usa `net.Listen("unix", …)` y no hay ningún archivo con build tag de Windows en `backend/` — en una máquina sin `AF_UNIX` el modo de aprobación por acción directamente no se ofrece (nunca se comporta como permisivo sin avisar). Lo resuelve la fase 7 del mismo plan, con `winio`
  /agentplan    plan de cada CLI, de lo que ya guardan: oauthAccount de ~/.claude.json (organizationRateLimitTier) y el claim chatgpt_plan_type del JWT de ~/.codex/auth.json — **del token solo se extrae ese campo, nunca sale el token**. Antigravity no publica su plan: se informa como desconocido en vez de inventarlo
  /agentmodels  catálogo de modelos y niveles de esfuerzo POR AGENTE, sacado de cada CLI en vez de escrito a mano: alias de Claude Code (no envejecen por definición), ~/.codex/models_cache.json (trae descripción y los esfuerzos que acepta CADA modelo) y `agy models`.   /mcpconf      config de servidores MCP de los tres CLIs: json.go (.mcp.json del proyecto, ~/.claude.json con sus servidores por proyecto, ~/.gemini/config/mcp_config.json de Antigravity y el settings.json de su nombre anterior) + write.go (escritura ACOTADA a los archivos que son configuración: preserva byte a byte lo que no toca, deja backup .mini-tools.bak, escribe atómico y NO reescribe un archivo ilegible; ~/.claude.json y el config.toml de Codex quedan fuera) + toml.go (~/.codex/config.toml, lector acotado a mano — ver sus límites documentados ahí; NO alcanza para escribir) + scan.go. **Los valores de `env` se descartan en la lectura: solo cruzan los nombres**

**Pestañas del editor con conexión/lenguaje propios (post-Redis):** cada `EditorTab` (`editor/EditorTabs.tsx`) tiene su propio `connId`/`language`, vinculado explícitamente vía un selector en la pestaña — nunca como efecto secundario de navegar el sidebar. `Workspace.tsx`'s `selected` (conexión expandida en el sidebar) y `activeTabConnection` (conexión de la pestaña activa) son estados independientes a propósito. Ver la sección dedicada en [.claude/skills/mini-tools-patterns/SKILL.md](../skills/mini-tools-patterns/SKILL.md) para el diseño completo (cache de metadata por conexión, el editor Monaco unificado con modelos por pestaña, y la retrocompatibilidad de `open_tabs`).

**Desviación del plan original:** la superficie de estado global se planeó con Zustand (`/state`) y un wrapper `wailsClient.ts`. En la práctica ninguno de los dos se necesitó — todo el estado del frontend es `useState`/props (ver `Workspace.tsx`), y los componentes importan `../../wailsjs/go/main/App` directamente. Ver [.claude/skills/mini-tools-patterns/SKILL.md](../skills/mini-tools-patterns/SKILL.md) sección "Fase 10" para el detalle de por qué se mantuvo así.

Ver el contrato completo de bindings Go↔React en [go-react-contract.md](go-react-contract.md), y el historial de decisiones/desviaciones fase por fase ahí mismo y en el SKILL del proyecto.
